# CodePool 产品定义

## 1. 定位

CodePool 不是完整密码管理器，也不是代码托管平台。它解决的是团队日常协作中“小而高频、需要共享、又不适合发在群里”的内容：一段部署命令、一个 2FA 动态码、测试环境的临时验证码、一小段配置或短期密文。

核心承诺：**取用足够快，边界足够清楚，发生过什么可以追溯。**

## 2. 内容模型

一个团队拥有一个或多个“池”，当前以团队作为池的安全边界。池内支持五类内容：

| 类型 | 示例 | 默认展示策略 |
| --- | --- | --- |
| `snippet` | Shell、SQL、配置片段 | 列表只展示标题和语言，详情显式读取 |
| `totp` | GitHub、云平台 2FA | 服务端计算当前码，不返回密钥 |
| `code` | 测试短信码、一次性兑换码 | 可设置过期时间 |
| `secret` | 临时 Token、只读凭据 | 显式读取并记审计 |
| `note` | 交接说明、操作提示 | 显式读取并记审计 |

## 3. 用户与权限

- `owner`：团队所有者，完整管理权限，不能被其他成员移除。
- `admin`：管理成员、TOTP、内容和分享。
- `member`：创建普通内容、读取被授权内容、创建短期分享。
- `guest`：只读，可配置成员级过期时间。

当前安全边界是团队级 RBAC。账号级 ACL 暂不进入 V1，避免同时维护两套容易冲突的权限体系；确有隔离需求时应拆分团队池。

## 4. V1 用户旅程

1. 用户微信登录，系统自动创建“我的代码池”。
2. 用户扫码导入 TOTP，或创建代码片段/一次性验证码。
3. 所有者生成短期邀请，成员加入团队。
4. 成员查看验证码或内容，系统记录不含正文的审计事件。
5. 成员可生成限时、限次分享，外部领取者无需登录。
6. 管理员在 Web 控制台查看团队、内容构成和异常操作。

## 5. 明确不做

- 不保存网站主密码和完整个人密码库。
- 不自动抓取短信或邮箱；这需要独立的渠道合规和隐私设计。
- 不宣称零知识或端到端加密。
- 不在管理端提供密钥、动态码或内容正文的批量导出。

## 6. 后续路线

- V1.1：内容编辑、分享撤销、审计筛选和过期内容自动清理。
- V1.2：内容级授权、敏感操作二次确认、恢复码。
- V2：PostgreSQL、多实例部署、企业 SSO、Webhook 安全通知。
- Enterprise：KMS 信封加密、审计归档、保留策略与私有化部署。
