# CodePool 安全模型

## 信任边界

CodePool 采用服务端可信模型，不宣称零知识或端到端加密。数据库文件泄露不应直接暴露正文，
但应用主机或主密钥完全失陷时，攻击者仍可能解密内容。小程序、运营后台、服务器、微信接口
和部署平台是不同信任边界。

## 已实现的防护

- AES-256-GCM 认证加密，每次写入使用独立 96-bit IV。
- JWT、内容主密钥与备份密钥相互独立；生产环境拒绝短密钥。
- 成员 JWT 包含会话版本；账号停用或注销后，全部旧令牌立即失效。
- 每次成员请求重新验证用户、团队、成员关系、内容状态与到期时间。
- 所有 SQLite 时间比较统一通过 `datetime(...)`，避免 ISO 字符串格式差异造成过期绕过。
- TOTP 列表不返回密钥或动态码；用户显式点击后才计算，并在切后台时清除。
- 分享和邀请只保存 token 摘要；匿名分享 GET/HEAD 不消费，POST 原子领取。
- 登录、动态码、敏感内容和匿名领取使用 SQLite 持久限流，429 带 `Retry-After`。
- 团队成员、内容、分享和邀请受运营配额与开关约束。维护模式暂停成员端新增、编辑、邀请领取
  和匿名分享领取；安全撤销、删除与注销仍保持可用。
- API 请求体最大 256 KiB；单项正文、标题和元数据另有字段级限制。
- 管理 Cookie 使用 `HttpOnly + Secure + SameSite=Strict`；变更请求校验来源。
- 管理员登录失败采用 HMAC 指纹持久限流和脱敏审计。
- CSP、HSTS、frame deny、nosniff、Referrer-Policy 与 Permissions-Policy 全局启用。
- API 默认 `no-store`；运营接口不返回正文、密钥、令牌、微信身份或原始 IP。
- 审计网络特征使用带服务端密钥的 HMAC，不保存可直接枚举的原始地址摘要。
- 注销完成会匿名化身份、撤销访问并保留必要的脱敏业务与审计关联。

## 加密备份

`npm run db:backup` 先使用 SQLite 在线备份生成一致性快照，再以独立备份密钥进行
AES-256-GCM 加密。`db:verify-backup` 会解密临时副本并执行 `integrity_check`。备份脚本只是
能力，不等于已经建立异地备份；调度、异地存储和告警仍必须在基础设施侧配置。

## 当前边界

- SQLite 限流与单实例部署匹配；水平扩容前应迁移 PostgreSQL/Redis 或其他集中式状态。
- 管理员仍为环境变量单账号，适合小团队自托管；企业版应使用管理员表、Argon2id、MFA、
  细分运营 RBAC 和会话设备管理。
- 内容加密暂未使用绑定 item/team 的 AAD，也没有密钥版本字段；主密钥轮换需专门迁移。
- 应用无法自行证明 Dokploy 卷是否已异地备份，必须建立外部可观测备份任务。
- v2/v3 治理状态无法由 v1 镜像解释；首次迁移后不得单独回滚旧镜像。
- 截屏、系统剪贴板和已被用户主动转发的数据超出应用可完全控制的范围。

## 上线安全闸门

1. 轮换曾暴露的 Dokploy、GitHub App、管理员和 JWT 凭据。
2. 注入独立主密钥、JWT 密钥与备份密钥；将恢复材料保存在服务器之外。
3. 配置微信 AppSecret、正式运营主体、客服、隐私指引和备案信息。
4. 完成加密备份、异地复制、恢复演练以及磁盘/备份失败告警。
5. 为 GitHub `main` 开启分支保护，要求 CI 通过后才能合并。
6. 运行 `npm run check` 和 `npm run smoke:security`，再做微信体验版弱网与真机验收。
